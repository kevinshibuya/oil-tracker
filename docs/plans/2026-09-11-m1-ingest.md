# Milestone 1 (Ingest) implementation plan

**Goal:** Turn three years of NOAA AIS for the Corpus Christi bounding box into a PostGIS store of tanker positions, vessels, berth visits and export events, cross-checked against PortWatch port calls.
**Architecture:** A uv-managed package `oiltracker` under `pipeline/` exposes the Typer CLI `oil`. Daily national AIS files stream through a bounding-box filter into one parquet per day; tanker rows load into a month-partitioned PostGIS `positions` table plus a per-day statics table. Terminal polygons are derived from the low-speed tanker positions around each terminal's published centre. A pure-Python state machine over per-vessel observation sequences yields berth visits and export events. One truth loader fills `portwatch_daily`; `oil report m1` is the acceptance gate.
**Spec:** `docs/design.md` (milestone 1; "Export event" and "Cargo per event" define the event record). Facts: `docs/research/data-sources.md`, `docs/research/q13-leg-a.md` sections 2 and 3.
**Execution model:** opus
**Scope notes (fix pass 2026-09-11):** Census monthly truth leaves this milestone and returns in milestone 3 with calibration; milestone 1 truth is PortWatch only. Terminal polygons are derived from data (Task 9), not digitised in a GUI, and checked against satellite imagery by computer use in Task 10; the spec is amended to match.
**Execution deviations (recorded during execution, 2026-09-11):** The database listens on host port **5434**, not 5433: 5433 is occupied on the executing machine by another project's container. `infra/docker-compose.yml` and the `Settings.database_url` default both say 5434. `postgis/postgis:16-3.4` is published for amd64 only, so on this arm64 machine the database runs emulated; kept as the plan names it, measured at the Task 6 load. Switching to an arm64 build stays cheap because the store rebuilds from the day parquet with `oil ais load`.

## Global constraints
- English everywhere: code, comments, commits, docs.

- Layout: `pipeline/`, `infra/docker-compose.yml` (`postgis/postgis:16-3.4`), `config/ports/`, `config/vessels/`, `data/` (git-ignored; `data/ais/<port>/<YYYY-MM-DD>.parquet`), `docs/`.

Feature-branch commits and pushes need no permission. Never run `git push` naming `main`. Every commit message ends with the two attribution lines the executing session is given.
- Per task, before its commit, in `pipeline/`: the acceptance check plus `uv run ruff check .`, `uv run ruff format --check .`, `uv run pyright`, `uv run pytest`, all passing, output shown in the same turn ("the four tool commands" below).
- Full-data runs that write `code_version` (`vessels build`, `port derive`, `events detect`) run only from committed code: the task's code commit precedes the run, and run outputs that are committed (the derived geojson) get their own commit.
- The dev server is already running; no task starts one. Nothing here renders.
- Bulk output goes to a `scout` and returns as a summary.
- Milestone 1 only: no globe, cargo estimation, satellite, live feed, EIA or Census. The only hook for later is the nullable cargo columns in `export_events`.
- Port bounding box default: latitude 27.55 to 28.05, longitude -97.60 to -96.60, configurable.
- Positions in PostGIS are tankers only: AIS `VesselType` 80 to 89, or `Cargo` 80 to 89. Their static fields go to `vessel_statics_daily`, one row per MMSI and day. Everything else stays in parquet.
- National files are never stored on disk in full; each worker stays under 2 GB RSS.
- Environment: `DATABASE_URL` (default `postgresql://oil:oil@localhost:5433/oil`), read through one `Settings` model only. Every connection runs with session timezone UTC.
- Derived rows carry `code_version` = `git rev-parse --short HEAD` at run time.
- Tests never skip: an unreachable database fails the run with a message naming `docker compose -f infra/docker-compose.yml up -d`.
- At the end: PR into `ai-staging`, manual-test rundown, stop. The review is the owner's to trigger.

create table ingest_manifest (

create table vessel_statics_daily (

  cargo smallint, transceiver_class text,
  primary key (port, mmsi, day));
create table positions (
  port text not null, mmsi integer not null, ts timestamptz not null,
  geom geometry(Point,4326) not null, sog real, cog real, heading real,

do $$ declare m date := '2023-01-01'; begin
  while m < '2025-10-01' loop

  dwell_hours real not null, low_speed_fraction real not null, observations integer not null,
  open_ended boolean not null,
  code_version text not null, unique (port, mmsi, terminal_id, entered_at));
create table export_events (
  id bigserial primary key,
  berth_visit_id bigint not null unique references berth_visits(id) on delete cascade,
  port text not null, mmsi integer not null, imo integer, name text,
  size_class text not null, size_class_source text not null, length_m real, width_m real,
  dwt_t real, tpc_t_per_cm real, scantling_draught_m real, particulars_source text,
  terminal_id text not null, polygon_version integer not null,
  entered_at timestamptz not null, exited_at timestamptz not null,
  gate_crossed_at timestamptz not null, hours_to_gate real not null, gate_interpolated boolean not null,
  arrival_draught_m real, arrival_draught_at timestamptz,
  departure_draught_candidates jsonb not null,
  chosen_departure_draught_m real, draught_reason_codes text[],
  method text, consumables_t real, raw_tonnes real, load_factor real, k_scalar real, fit_window_id text,
  density_bbl_per_t real, barrels real, next_destination text, sts_flag boolean,
  code_version text not null, created_at timestamptz not null default now());
create table portwatch_daily (
  date date not null, portid text not null, portcalls integer, portcalls_tanker integer,

**Interfaces:**
- Consumes: `SourceSpec`, `load_sources`, `url_for`, `PortConfig.bbox`, `Settings`, `connect`, `ingest_manifest`.
- Produces: `oil ais backfill --port corpus_christi --from 2023-01-01 --to 2025-09-30 [--workers 2]`; `oil ais fixture --port corpus_christi --day 2024-03-05`; parquet columns `mmsi int32, ts timestamp[us, UTC], lat float64, lon float64, sog float32, cog float32, heading float32, vessel_name string, imo int32, call_sign string, vessel_type int16, status int16, length_m float32, width_m float32, draught_m float32, cargo int16, transceiver_class string`.

**Work:** Header mapping is case-insensitive from the probed header (`BaseDateTime` to `ts`, `Draft` to `draught_m`, `Length` to `length_m`, `Width` to `width_m`); a missing required column is a hard error naming the year. Sentinel values become null in the mapping: `Draft <= 0`, `Length <= 0`, `Width <= 0`, `SOG >= 102.3`, `COG >= 360`, `Heading = 511`; `IMO` loses a leading `IMO` prefix and a non-numeric remainder becomes null. Stream with httpx through zstandard or stream-unzip into `pyarrow.csv.open_csv` in blocks of about 500k rows; bbox-filter per block; write `<day>.parquet.tmp`, rename on success. Manifest contract: on start upsert `(port, day)` with `status='running'`, `source_url`, `format`, `started_at`; on success `done` with `bytes` streamed, `rows_kept`, `finished_at`; on exception `failed` with `error`, written before re-raising. Source fallback: `backfill_day` tries the year's specs in order; an HTTP 404 moves to the next; when every spec returns 404 the day is `missing` (no parquet, `finished_at` set) and counts as complete. Any other error is `failed`. `backfill` skips a `done` day whose parquet exists and every `missing` day; it retries `failed`, and `running` older than six hours; it catches per-day failures and continues. Workers run days concurrently, each with its own `connect(settings)` connection. **Interfaces:**
- Consumes: `PortConfig`, `Terminal`, `current_terminals`, `positions`, `vessels`, `upsert_terminals`, `load_day`, `build_vessels`.
- Produces: `oil events detect`; rows in `berth_visits`, `export_events`.

**Work:** `detect_port` reads the port's polygons with `current_terminals(conn, cfg.id)` (the maximum version in `terminals`), streams each tanker's positions ordered by `ts`, runs the pure functions, deletes the port's rows in both tables, inserts fresh. The state machine, verbatim:

1. Labels. Each `Obs` gets `terminal`: the terminal whose polygon covers `(lat, lon)`, else none; when several cover it (possible only for version-0 seeds), the one whose polygon centroid is nearest. `side` = `gate_side`: the sign of the cross product of `b − a` and `p − a`, oriented so that `harbour_reference` is −1; +1 is seaward; 0 exactly on the line.
2. Runs. Walk the vessel's observations in `ts` order with no open run. An observation inside terminal T opens a run at T with `entered_at = ts`. Every later observation inside T extends the run (`last_inside = ts`) whatever the gap since the previous observation: a long gap that ends inside T is one visit, not two. Observations not inside T (outside every polygon, or inside another terminal) form an excursion. The run ends, with `exited_at = last_inside`, at the first of: (a) an excursion observation more than `gap_tolerance_hours` after `last_inside`; (b) an excursion whose observations span `exit_confirm_minutes` or more, from its first observation to the current one with no inside-T observation between; (c) the end of the observations. `open_ended` is true for (c), false for (a) and (b). An excursion that returns inside T before (a) or (b) is tolerated; its observations belong to no run and count in nothing. After a run ends, processing resumes at the observation after `exited_at` with no open run, so an excursion that ended one run can open a run at another terminal.
3. Visits. A run is a berth visit when `exited_at − entered_at ≥ dwell_min_hours` and `low_speed_fraction ≥ low_speed_fraction_min`, where `low_speed_fraction` is the share of the run's inside-T observations with non-null `sog` that have `sog < low_speed_knots` (0 when none has a `sog`). `observations` is the count of inside-T observations; `dwell_hours = exited_at − entered_at` in hours. Other runs are discarded. Open-ended visits are recorded like any other.
4. Departure. An open-ended visit gets no scan. Otherwise the scan covers the observations from the visit's exit observation (the one at `exited_at`) through the last observation at or before `min(exited_at + departure_window_hours, next_entered_at)`, where `next_entered_at` is the `entered_at` of the vessel's next visit at any terminal, or nothing. There is no other polygon test: a later visit bounds the scan; polygon contact that does not become a visit is ignored. Observations with `side = 0` are skipped. Walk the remaining observations in order with `prev` the previous kept observation, seeded with the exit observation. A departure is the first pair `(prev, cur)` with `prev.side = −1` and `cur.side = +1` for which either: (i) the straight segment from `prev` to `cur` intersects the gate segment `a–b` (`gate_crossing` returns the time): `gate_crossed_at = prev.ts + (cur.ts − prev.ts) × (distance from prev to the intersection point ÷ segment length)`, `gate_interpolated = false`; or (ii) `cur.ts − prev.ts > gap_tolerance_hours`: `gate_crossed_at` is the midpoint of `prev.ts` and `cur.ts`, `gate_interpolated = true`. A −1/+1 pair that meets neither is not a crossing and the walk continues. No departure in the scan: the visit stays a visit without an event.
5. Plateaus. Over the observations with non-null `draught_m` in `[start, end]`, in order: a run extends while `max − min ≤ plateau_max_range_m` with the new observation included; otherwise it closes and a new run starts at that observation. A run with at least `plateau_min_obs` observations spanning at least `plateau_min_span_minutes` is a plateau: `draught_m` the median, `at` the last observation's `ts`, `observations` the count. Gaps between observations do not break a run.
6. Arrival and candidates, computed for visits with a departure. Arrival: the plateau with the latest `at` in `[entered_at − arrival_lookback_hours, entered_at]`, else null, with `arrival_draught_at = at`. Candidates: every plateau in `[exited_at − candidates_before_exit_hours, exited_at + candidates_after_exit_hours]`, ordered by `at`, each `{draught_m, at, hours_after_exit, observations}` with `hours_after_exit = (at − exited_at)` in hours, negative allowed; the plateau ending at berth exit is a candidate by design (q13 section 3 opens the window 6 h before exit). `[]` when none. Chosen value and reason codes stay null.
7. Event row. One per visit with a departure, joining identity, class, particulars and sources from `vessels` by MMSI (a missing `vessels` row is a hard error naming the MMSI: `build_vessels` runs before `detect_port`); `polygon_version` the terminal's version; `hours_to_gate = (gate_crossed_at − exited_at)` in hours.

Synthetic tracks in `test_detect.py` use square polygons 400 m across centred on the three A8 centres, version 0, and the real `PortConfig` defaults; observations every 5 minutes unless stated; `t0` is the first inside observation. Expected results, derived from the rules above:
